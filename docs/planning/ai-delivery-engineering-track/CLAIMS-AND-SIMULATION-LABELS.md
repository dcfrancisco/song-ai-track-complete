# Curriculum Claims and Simulation Labels

## Purpose

Preserve the educational value of Labs 1–10 while ensuring that documentation does not imply production maturity that the implementation does not demonstrate.

## Required Terminology

- **Foundational** — teaches a concept with intentionally bounded scope.
- **Introductory** — demonstrates a pattern without production controls.
- **Demonstration** — proves that a concept can be exercised end to end.
- **Simulated** — uses local mocks, generated values, in-memory state, or placeholder integrations.
- **Production-oriented extension** — adds controls such as persistence, authorization, evaluation, resilience, observability, or recovery.

## Current Lab Boundaries

- The current in-memory product-vector RAG is foundational/demo RAG, not production RAG.
- The current JSON-in-model-text order flow is a tool-selection demonstration, not secure native tool execution.
- The current local order methods are simulated integrations, not OMS, CRM, subscription, payment, or returns systems.
- The current specialist catalog/content/SEO prompts are conventional orchestration, not enterprise multi-agent coordination.
- Current provider switches are configuration abstraction, not provider routing or failover.
- Current console logging and elapsed-time output are introductory diagnostics, not full observability or audit.

## Claim Review Rule

Every Level 2+ claim must point to implementation evidence, automated evidence, and documented limitations. A prompt is not a security or governance boundary, and multiple prompts do not automatically constitute a multi-agent system.
